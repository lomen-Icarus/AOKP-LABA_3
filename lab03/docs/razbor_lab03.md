# Разбор лабораторной №3: сцена, матрица модели и модуль GraphicObject

## Что от тебя требуется

Вывести четыре объекта разных цветов (красный, синий, зелёный, белый) на осях OX и OZ так, чтобы их «носики» смотрели в центр сцены. Камера стоит в точке (10, 15, 17.5) и смотрит в начало координат, фон чёрный. Логика объекта вынесена в отдельный модуль `graphic_object.rs`, объекты хранятся в `Vec<GraphicObject>`. Код проходит `cargo fmt` и `cargo clippy` без предупреждений.

Оригинал задания написан для C++ и OpenGL с чайниками из freeglut. В переносе на Bevy модель — тор. У тора нет носика, поэтому в решении к тору добавлен маленький конус вдоль локальной +X: без него направление объекта на картинке проверить нельзя.

## Четыре сущности трёхмерной графики

| Понятие | В оригинале (OpenGL) | В Bevy |
|---|---|---|
| Модель | `glutWireTeapot`, носик вдоль +X | `Mesh` в `Assets<Mesh>`, создаётся один раз |
| Графический объект | класс `GraphicObject` с `modelMatrix[16]` | компонент `GraphicObject` + компонент `Transform` |
| Сцена | глобальные переменные и `display()` | `World` с сущностями, `Startup`-система |
| Наблюдатель | `gluLookAt(10, 15, 17.5, 0, 0, 0, 0, 1, 0)` | `Camera3d` + `Transform::from_xyz(...).looking_at(...)` |
| Проекция и viewport | `gluPerspective` в `reshape` | плагин камеры, перспектива по умолчанию |

Матрица модели переводит вершины из локальной системы координат в мировую. Матрица вида переводит мир в систему координат камеры. Матрица проекции делает из трёхмерных координат двумерные. В Bevy ты задаёшь только первую (через `Transform` объекта) и косвенно вторую (через `Transform` камеры).

## Как построить матрицу модели

В оригинале матрица собиралась из трёх осей и позиции:

```
| ox.x  oy.x  oz.x  p.x |
| ox.y  oy.y  oz.y  p.y |
| ox.z  oy.z  oz.z  p.z |
| 0     0     0     1   |
```

Правила: оси единичной длины, взаимно перпендикулярны, правая тройка. Для правого чайника в (4, 0, 0) носик должен смотреть влево, поэтому ось Ox становится (−1, 0, 0). Одного знака мало: тройка станет левой, и объект отразится зеркально. Поэтому меняется и Oz: (0, 0, −1). Это ровно поворот на 180° вокруг Oy.

В Bevy ту же матрицу даёт `Transform::from_translation(position).with_rotation(Quat::from_rotation_y(angle))`. Кватернион гарантирует все три правила автоматически: поворот не меняет длину осей, не ломает перпендикулярность и не меняет ориентацию тройки. Проверка: [Transform](https://docs.rs/bevy/0.19.1/bevy/prelude/struct.Transform.html), [Quat::from_rotation_y](https://docs.rs/glam/latest/glam/f32/struct.Quat.html#method.from_rotation_y).

## Знак угла

В задании угол задан «по часовой стрелке вокруг Oy». `Quat::from_rotation_y(θ)` при положительном θ поворачивает против часовой стрелки, если смотреть сверху (с +Y). Поэтому в `to_transform()` стоит `-self.angle_deg.to_radians()`. Формула: локальная +X после поворота на θ равна `(cos θ, 0, −sin θ)`.

| Объект | Позиция | Угол | θ = −угол | Носик `(cos θ, 0, −sin θ)` | Куда смотрит |
|---|---|---|---|---|---|
| Красный | (4, 0, 0) | 180° | −180° | (−1, 0, 0) | в центр |
| Синий | (−4, 0, 0) | 0° | 0° | (1, 0, 0) | в центр |
| Зелёный | (0, 0, −4) | 90° | −90° | (0, 0, 1) | в центр |
| Белый | (0, 0, 4) | 270° | −270° | (0, 0, −1) | в центр |

Если убрать минус, зелёный и белый поменяются местами по направлению и будут смотреть от центра. Тест `four_noses_point_to_scene_center` ловит именно эту ошибку.

## Класс против компонента

В C++ поля были приватными, а сеттеры вызывали `recalculateModelMatrix()`. В ECS данные и поведение разделены:

- `GraphicObject` — компонент с тремя полями: `position`, `angle_deg`, `color`.
- `to_transform()` и `to_color()` — чистые методы, аналог `recalculateModelMatrix`.
- `spawn_graphic_object()` — аналог `draw()`: создаёт сущность с мешем, материалом и `Transform`.
- `sync_graphic_objects` — система с фильтром `Changed<GraphicObject>`. Когда любое поле изменилось, `Transform` и цвет материала пересчитываются. Это замена приватным сеттерам: Bevy сам отслеживает изменения компонента. Проверка: [Changed](https://docs.rs/bevy/0.19.1/bevy/ecs/query/struct.Changed.html).

Модель хранится один раз: `GraphicModel` создаёт два меша (тор и носик) и раздаёт handle. Тест `startup_spawns_four_objects_sharing_one_model` проверяет, что в `Assets<Mesh>` ровно два меша при четырёх объектах.

## Модуль

`mod graphic_object;` в `lib.rs` подключает файл `src/graphic_object.rs`. Это аналог пары `GraphicObject.h` + `GraphicObject.cpp`. Защита от повторного включения (`#pragma once`) в Rust не нужна: модуль компилируется один раз. Публичный интерфейс задаётся словом `pub`, остальное приватно по умолчанию, как секция `private` в классе.

Крейт разделён на библиотеку (`lib.rs`: плагин, системы, список объектов) и исполняемый файл (`main.rs`: только окно). Это позволяет тестам и примеру `capture` использовать тот же плагин, что и приложение.

## Носик и дочерняя сущность

Конус Bevy направлен вершиной вдоль +Y. Поворот на −90° вокруг Z укладывает его вдоль +X. Конус — дочерняя сущность тора (`children!`), поэтому его `Transform` задан в локальной системе координат родителя и автоматически следует за поворотом тора. Проверка: [Cone](https://docs.rs/bevy/0.19.1/bevy/prelude/struct.Cone.html), [children!](https://docs.rs/bevy/0.19.1/bevy/prelude/macro.children.html).

## Дополнительное задание: обращение вокруг центра

Клавиша `R` включает режим, в котором каждый кадр позиция поворачивается вокруг Oy на `ω · Δt`, а угол уменьшается на ту же величину. Поворот позиции и носика на один угол сохраняет направление на центр. Красный объект после поворота на 90° занимает место зелёного: позиция (0, 0, −4), угол 90°. Это проверяет тест `quarter_turn_moves_red_into_green_slot`.

## Как написать свою версию

1. Размести два тора вручную в `Startup` через `Transform::from_xyz` и `with_rotation`. Добейся, чтобы носики смотрели друг на друга.
2. Заведи структуру `GraphicObject` с тремя полями и `to_transform()`. Проверь таблицу знаков выше.
3. Напиши `spawn_graphic_object` и `Vec<GraphicObject>` из четырёх элементов.
4. Вынеси всё в `graphic_object.rs`, добавь `pub`.
5. Поставь камеру в (10, 15, 17.5), фон чёрный, сравни с примером.
6. Запусти `cargo fmt`, `cargo clippy --all-targets -- -D warnings`, `cargo test`.

## Вопросы для защиты

| Вопрос | Короткий ответ |
|---|---|
| Что такое матрица модели? | Перевод вершин из локальной системы координат в мировую. |
| Почему нельзя просто поменять знак оси Ox? | Тройка станет левой, объект отразится. Нужно менять и Oz, то есть повернуть на 180°. |
| Зачем минус перед углом? | В задании угол по часовой стрелке, `from_rotation_y` крутит против. |
| Где аналог `recalculateModelMatrix`? | `to_transform()` и система с `Changed<GraphicObject>`. |
| Почему модель хранится один раз? | Четыре объекта ссылаются на один меш по handle, память не дублируется. |
| Что заменяет `#pragma once`? | Ничего: модуль Rust компилируется однократно по построению. |
| Как проверить, что носик смотрит в центр? | Скалярное произведение направления носика и вектора к центру близко к 1. |
